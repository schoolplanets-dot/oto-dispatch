# Оперативная диспетчеризация инженеров ОТО (модуль для «Админавтотрап»)

Решение помогает начальнику смены выбрать исполнителя по заявке на неисправность ВС, даёт инженеру маршрут до самолёта и контролирует норматив **«инженер у ВС в течение 15 минут с момента фиксации заявки»**. Модуль встроен в исходную программу и **не заменяет** её: цепочка «сообщение → фиксация → обработка диспетчером → назначение → работа» продолжена, исходная программа остаётся доступной и не изменена (кнопка «← Исходная программа», либо `?mode=orig`).

## Состав поставки

| Файл / каталог | Что это |
|---|---|
| `dist/Админавтотрап_ОТО.html` | **Главный результат**: исходная программа + модуль, один HTML-файл, работает офлайн |
| `docs/API_контракт.md`, `docs/openapi.json` | REST-контракт (56 методов), приложение к решению |
| `src/core/` | серверная логика (изоморфный JS): классификатор, подбор, маршрутизация, норматив, журнал, REST-маршрутизатор |
| `src/client/` | клиентские интерфейсы: диспетчер, инженер (телефон), журнал, интеграция/имитатор, классификатор, локация, API |
| `server/node-server.js` | отдельный REST-сервер (HTTP + JSON, CORS), хранилище — файл JSON |
| `data/` | пакеты локаций (Шереметьево — учебная схема, условный аэродром «Б») |
| `build.js` | сборка единого HTML из исходной программы (`original.html`) и модуля |
| `tools/`, `test/` | генератор пакетов и документации, автотесты (Node) и браузерные тесты (Playwright) |

## Как пользоваться

1. Откройте `dist/Админавтотрап_ОТО.html` в браузере. По умолчанию открывается модуль диспетчеризации; исходная программа — по кнопке «← Исходная программа» (для неё действует её собственный вход по PIN, как и раньше). Кнопка «✈ Диспетчеризация ОТО» в исходной программе возвращает в модуль.
2. Вход (учебные PIN подставляются при выборе пользователя):
   - начальник смены `SM-01` — PIN 2468;
   - инженеры `AG-01…AG-08` — PIN 3381, 4292, 5203, 6114, 7025, 7936, 8847, 9758 (те же, что в исходной программе);
   - сервисные учётные записи для внешних систем: `svc-sim` / `sim-key-0001`, `svc-aodb` / `aodb-key-0001`.
3. Вкладка **«Интеграция и имитатор»**: запуск сценариев (одна заявка; AOG и две срочные одновременно; нужен подъёмник/автотрап; удалённая стоянка; ВС ещё не прибыло; ВС буксируется рядом с маршрутом; инженер задержался; дубликат из двух каналов; некорректные данные; авария канала GPS), ускорение времени (×1…×60), отказ каналов, ручной опрос внешнего источника по URL. Имитатор работает **только через REST-контракт**, как реальные агенты.
4. Вкладка **«Инженер (телефон)»** — эмуляция телефона выбранного инженера (принять/отклонить, статусы, этапы, AOG/MEL, маршрут, шаги по маршруту, тап по карте, передача GPS браузера). Инженер, вошедший под своей учётной записью, видит только телефон.
5. **Журнал** — события с точностью до секунды, фильтры, выгрузка в Excel (XLSX) и CSV (одна строка — одно событие).

### Отдельный REST-сервер

```bash
node server/node-server.js --port 8080 --sim          # --sim: серверный имитатор положения; --scale 10; --reset; --pack SVO-DEMO|ZIA-DEMO
# интерфейс поверх реального сервера: открыть dist/Админавтотрап_ОТО.html?api=http://localhost:8080
curl localhost:8080/api/v1/contract
```

## Web-приложение по карте аэродрома (слои QGIS)

Карта строится из четырёх слоёв GeoJSON (WGS 84), выгруженных из QGIS. Исходные файлы лежат в `data/geo/`, файлы `.qmd` — метаданные QGIS (система координат EPSG:4326).

| Слой | Что из него получается |
|---|---|
| `airport_boundaries.geojson` | граница аэродрома: контур на карте, охват карты и допустимая область координат |
| `service_zones.geojson` | 10 зон обслуживания → места стоянок МС-1…МС-10, привязанные к ближайшей дороге спецтранспорта |
| `roads.geojson` | граф дорог (1091 узел, 1177 участков). `service` — спецтранспорт и пешком, класс скорости берётся из `spd_kmh` (5 / 8 / 10 / 20 км/ч → классы Системных требований). `pedestrian` — только пешком. `taxi`/`runway` — только ВС, по ним строятся рулёжные маршруты имитатора |
| `objects.geojson` | Терминал, Ангар (база ОТО), Стоянка спецтехники (парк транспорта), Склад №1 и №2 (склады инструмента). ВПП становится запретной зоной: маршруты через неё не строятся |

Пакет `GEO-MAP` собирается командой `node tools/geo-pack.js` (модуль `src/core/geoimport.js`) и теперь открывается по умолчанию. Учебные схемы остаются на вкладке «Локация» и открываются по `?pack=SVO-DEMO`. Новые слои можно загрузить прямо в интерфейсе на вкладке «Карта» → «Слои GeoJSON», без правки кода.

**Вкладка «Карта»** — полноэкранный фрейм карты:
- подложка: без подложки, OpenStreetMap или спутник Esri, с регулируемой прозрачностью;
- слои: дороги, раскраска по скорости спецтранспорта, стоянки и объекты, ВПП, ВС, инженеры, транспорт, маршруты;
- свойства любого объекта по щелчку, включая атрибуты исходного слоя (`fid`, `type`, `spd_kmh`, `commentary`);
- координаты под курсором, масштабная линейка;
- пробный маршрут «откуда → куда» пешком или на спецтранспорте: время, разбивка по скоростям, проверка норматива 15 мин.

**Запуск web-приложения.** Нужен Node 18+, внешних зависимостей нет:

```
node tools/geo-pack.js && node build.js
node server/node-server.js --port 8080 --sim      # или: npm start, или: docker compose up -d --build
```
Установка на собственный сервер через Docker (Compose, HTTPS через nginx, свои PIN, резервные копии, обновление, работа без интернета): **docs/Развёртывание_Docker.md**.


Откройте `http://<сервер>:8080/` на компьютере начальника смены и на телефонах инженеров. Все клиенты работают с одним сервером через REST API (same-origin), и данные общие.

Приложение устанавливается на экран телефона как PWA: в Safari «Поделиться → На экран „Домой“». Service worker кэширует оболочку и тайлы подложки; оперативные данные всегда берутся из сети.

Исходная программа доступна по `/?mode=orig`. Её командный чат подключается к серверному каналу WebSocket `/ws/chat` и становится общим между устройствами. Код исходной программы не менялся.

Открытый двойным щелчком HTML-файл по-прежнему работает автономно (встроенный сервер), и имитатор в этом режиме запускается в самой странице. В режиме web-приложения имитатор работает на сервере (`--sim`).

## Архитектура (4 слоя)

1. **Клиентские интерфейсы** — диспетчер (карта, заявки, кандидаты, прогноз, оповещения), инженер (телефон), журнал, интеграция/имитатор, классификатор, локация, API.
2. **Серверная логика** — классификатор дефектов, подбор исполнителя (допуски, расстояние/время, загрузка, этап уже начатых работ, срочность/AOG, спецтранспорт, оснащение), маршрутизация по графу, расчёт и прогноз норматива, статусная машина с проверкой переходов и ролей.
3. **Хранилище** — состояние и журнал: в браузере (`localStorage`) или в файле (`data/runtime/store.json`) на Node-сервере; интерфейс хранилища (адаптер) допускает замену на БД.
4. **Интеграционный слой** — REST/JSON, приём положений (инженеры, транспорт, ВС), расписание (AODB), опрос внешних URL, статусы каналов online/stale/offline, работа на последних известных данных при сбое.

В браузере сервер выполняется внутри страницы за виртуальным транспортом (те же маршруты и тот же код, что на Node); на вкладке «API и архитектура» есть консоль запросов.

## Соответствие требованиям

| Требование | Реализация |
|---|---|
| Встраивание в цепочку, роли, статусы | Роли: начальник смены, инженер, интеграция; статусы new → in_review → offered → assigned → en_route → on_site → in_progress → done → closed (+ cancelled) с проверкой переходов; переназначение после начала работ — только начальником смены и с причиной |
| Приём и классификация | Источники: экипаж, сотрудник, телефон, внешняя система, диспетчер; свободный текст → категория, глава ATA, тип дефекта; справочник расширяется (вкладка «Классификатор»); инженер ставит AOG и MEL |
| Подбор исполнителя | Допуск по типу ВС и главе ATA, время прибытия, загрузка, этап начатых работ, срочность; план по нескольким срочным/AOG заявкам; объяснение: причины выбора и причины отклонения остальных |

| Положение | Приём от агентов и внешних систем (одиночно и пакетом), проверки, устаревание, журнал ошибок приёма |
| Журнал и экспорт | События с точностью до секунды (фиксация, кандидаты с обоснованием, назначения, статусы, переназначения, маршруты, ожидаемое и фактическое прибытие ВС и инженера, риск, нарушение, ошибки данных); длительность процессов; XLSX/CSV |
| Системные требования | Скорости: пешком 5 км/ч; спецтранспорт 5 / 8 / 10 / 20 км/ч по классам участков (`speedClass`); задержки: посадка 10 с, высадка 10 с, получение инструмента 30 с. Параметры `footKmh`, `vehicleKmh`, `boardingS`, `alightingS`, `toolPickupS`; учтены в подборе, прогнозе норматива, маршрутах, журнале и имитаторе; вкладка «Системные требования» (редактирование + контрольный расчёт). Проверка: `node test/sysreq.js` |

Сервер раздаёт приложение (PWA), REST API и WebSocket-чат исходной программы. Проверка: `node test/geo.js`, `python3 test/b14.py`, `python3 test/b15.py` |
| REST API | `docs/API_контракт.md`, `GET /api/v1/contract` |
| Переносимость | Схема аэродрома — пакет локации (JSON); переключение/загрузка/скачивание на вкладке «Локация» без изменения кода |

## Ограничения (честно)
- Координаты слоёв QGIS лежат в районе ВДНХ (Москва), поэтому на подложке OSM или на спутнике под схемой аэродрома видна городская застройка. Привязка точная, но подложка носит справочный характер; по умолчанию она выключена.
- Тайлы OpenStreetMap и Esri загружаются из интернета и требуют указания авторства (оно выводится на карте). Для промышленной эксплуатации нужен собственный тайл-сервер или ортофотоплан аэродрома.
- Состав объектов определяется по названию (терминал, ангар, склад, стоянка спецтехники, ВПП). Объект с другим названием отображается как здание.
- Начальные данные для карты (инженеры, транспорт, ВС на стоянках) учебные и генерируются автоматически.

- Карта — схематичный SVG по пакету локации, не подложка реальной карты. Демо-данные (аэродром, сотрудники, ВС, допуски) — учебные.
- В HTML-файле сервер встроен в страницу (виртуальный транспорт); реальный HTTP — отдельный `server/node-server.js`. Аутентификация — учебная (PIN), не заменяет корпоративную; для промышленной эксплуатации нужны TLS, внешний SSO, БД.
- Геопозиция браузера принимается, только если она лежит в границах пакета локации; иначе отклоняется и записывается в журнал как ошибка приёма. Для проверки на телефоне используйте шаги по маршруту, тап по карте или автопилот имитатора.
- Учёт наличия инструмента — параметр `considerInventory` (по умолчанию включён): влияет только на типы дефектов с `requiredTools` и инженеров без этого инструмента; склад запчастей не моделируется.
- Скорости 5/8/10/20 км/ч — средние, по классам участков; разгон, торможение и маневры внутри участка не моделируются. Класс «вдоль терминалов» определён по геометрии пакета (участки перронной дороги в пределах протяжения терминала).
