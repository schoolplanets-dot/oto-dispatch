# Развёртывание web-приложения ОТО на собственном сервере (Docker)

Инструкция описывает установку web-приложения «Админавтотрап · оперативная диспетчеризация инженеров ОТО» на свой сервер. После установки один сервер отдаёт исходный интерфейс программы с вкладкой «Карта», REST API `/api/v1`, командный чат `/ws/chat` и, если нужно, имитатор. Начальник смены и инженеры с телефонов работают с общими данными.

Все команды ниже проверены на чистой сборке образа: запуск, вход, создание заявки, перезапуск с сохранением данных, чат через nginx, имитатор, проверка работоспособности и замена учебных PIN. Сквозная проверка лежит в `test/docker-e2e.sh`.

---

## 1. Что понадобится

| Что | Минимум | Рекомендуется |
|---|---|---|
| Сервер | Linux x86-64 или ARM64 (Ubuntu 22.04/24.04, Debian 12, Astra, РЕД ОС и т. п.) | Отдельная ВМ в сети аэропорта |
| Ресурсы | 1 vCPU, 512 МБ ОЗУ, 1 ГБ диска | 2 vCPU, 1 ГБ ОЗУ |
| ПО | Docker Engine 24+ с плагином Compose v2 | Docker 26+ |
| Сеть | Входящий TCP-порт 8080 (или 80/443 через nginx) | Доменное имя и HTTPS |
| Интернет | Нужен только при сборке, чтобы скачать базовый образ `node:22-alpine` | Подложка OSM или спутник на карте тоже берёт тайлы из интернета, сама схема аэродрома работает без него |

Внешних npm-зависимостей у приложения нет: `npm install` не нужен.

**HTTPS обязателен, если инженеры ставят приложение на iPhone («На экран „Домой“») и нужен офлайн-кэш (service worker).** По обычному `http://` в локальной сети приложение работает полностью, но без кэша PWA.

## 2. Установка Docker (один раз)

Ubuntu или Debian:

```bash
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER        # чтобы запускать docker без sudo; затем перелогиньтесь
docker --version && docker compose version
```

Для закрытых сетей без доступа к get.docker.com поставьте пакеты из своего зеркала: `sudo apt install docker.io docker-compose-v2`. Если и это недоступно, используйте вариант с переносом готового образа (раздел 10).

---

## 3. Перенос проекта на сервер

Со своего компьютера:

```bash
scp ОТО_диспетчеризация.zip user@SERVER:/tmp/
```

На сервере:

```bash
sudo mkdir -p /opt/oto && sudo chown $USER /opt/oto
cd /opt/oto
unzip /tmp/ОТО_диспетчеризация.zip        # если нет unzip: sudo apt install unzip
ls    # Dockerfile  docker-compose.yml  deploy/  server/  src/  data/  web/  dist/ ...
```

Имя каталога (`oto`) становится именем проекта Compose, а том с данными будет называться `oto_oto-data`.

## 4. Настройка

Все параметры задаются в `docker-compose.yml`, в разделе `environment`. Код менять не нужно.

| Переменная | По умолчанию | Значение |
|---|---|---|
| `PORT` | `8080` | Порт внутри контейнера. Внешний порт задаётся в `ports:` слева от двоеточия |
| `SCALE` | `1` | Ускорение времени: `1` — реальное время (эксплуатация), `10` — демонстрация и испытания |
| `SIM` | `0` | `1` — имитатор движения ВС, спецтранспорта и инженеров (учебный режим, работает только с учебными PIN) |
| `PACK` | `GEO-MAP` | Локация: `GEO-MAP` — карта по слоям QGIS; встроенные демо-локации `SVO-DEMO`, `ZIA-DEMO` |
| `TZ` | `Europe/Moscow` | Часовой пояс журналов |
| `OTO_PINS` | не задано | Свои PIN и ключи вместо учебных, например `"SM-01=7391,AG-01=5520,AG-02=6604,svc-aodb=длинный-ключ"` |
| `OTO_DEMO` | `1` | `0` — не подставлять учебные PIN на экране входа |

Есть два типовых набора настроек.

**Испытания и демонстрация.** Учебные PIN, имитатор, ускоренное время:

```yaml
      SCALE: 10
      SIM: 1
```

**Эксплуатация.** Реальное время, без имитатора, свои PIN:

```yaml
      SCALE: 1
      SIM: 0
      OTO_PINS: "SM-01=7391,AG-01=5520,AG-02=6604,AG-03=1187,AG-04=9032,AG-05=4471,AG-06=2850,AG-07=6319,AG-08=8046"
      OTO_DEMO: 0
```

PIN применяются при каждом запуске контейнера и сохраняются после смены локации. Учётные записи, которых нет в `OTO_PINS`, сохраняют учебные PIN, поэтому для эксплуатации перечислите все. Учебные значения: SM-01/2468, AG-01…AG-08: 3381, 4292, 5203, 6114, 7025, 7936, 8847, 9758, интеграции svc-sim/sim-key-0001 и svc-aodb/aodb-key-0001.

Чтобы PIN не лежали в самом `docker-compose.yml`, вынесите их в файл `.env` рядом с ним и закройте доступ к нему: `chmod 600 .env`. Содержимое `.env`:

```
OTO_PINS=SM-01=7391,AG-01=5520
```

В `docker-compose.yml` тогда укажите `OTO_PINS: ${OTO_PINS}`.

## 5. Сборка и запуск

```bash
cd /opt/oto
docker compose up -d --build
```

При сборке образ собирает локацию из слоёв QGIS (`data/geo/*.geojson` → `data/pack-geo-map.json`) и единый HTML (`dist/`). Первая сборка занимает 1–2 минуты, следующие — секунды.

Проверка:

```bash
docker compose ps                    # STATUS: Up … (healthy)
docker compose logs --tail 20 oto    # «OTO REST-сервер: … (ускорение ×1, локация GEO-MAP)»
curl -s http://127.0.0.1:8080/api/v1/health    # {"ok":true,"version":"1.0",...}
```

Откройте в браузере `http://IP-СЕРВЕРА:8080/`:

- компьютер начальника смены: вход SM-01, вкладки «Диспетчер» и «Карта»;
- телефоны инженеров: вход AG-01…AG-08, экран своего задания;
- исходная программа без изменений: `http://IP-СЕРВЕРА:8080/?mode=orig`.

Если порт закрыт межсетевым экраном, откройте его:

```bash
sudo ufw allow 8080/tcp        # только если nginx (раздел 6) не используется
```

## 6. HTTPS и доменное имя (nginx + Let's Encrypt)

Нужен для установки на iPhone как приложения и для работы через интернет.

**6.1.** Сделайте порт приложения доступным только самому серверу. В `docker-compose.yml`:

```yaml
    ports:
      - "127.0.0.1:8080:8080"
```

Затем примените изменение: `docker compose up -d`.

**6.2.** Установите nginx и certbot:

```bash
sudo apt install -y nginx certbot python3-certbot-nginx
```

**6.3.** Подключите готовую конфигурацию из проекта. В ней настроено проксирование WebSocket для чата `/ws/chat` и разрешена загрузка GeoJSON-слоёв размером до 20 МБ.

```bash
sudo cp deploy/nginx-oto.conf /etc/nginx/sites-available/oto
sudo sed -i 's/oto.example.ru/ВАШ-ДОМЕН/' /etc/nginx/sites-available/oto
sudo ln -s /etc/nginx/sites-available/oto /etc/nginx/sites-enabled/oto
sudo nginx -t && sudo systemctl reload nginx
```

**6.4.** Получите сертификат. Домен должен указывать на сервер (DNS-запись A), порт 80 должен быть открыт.

```bash
sudo ufw allow 'Nginx Full'
sudo certbot --nginx -d ВАШ-ДОМЕН --redirect
```

Certbot сам добавит блок `listen 443 ssl` и автоматически продлевает сертификат.

**Внутренняя сеть без выхода в интернет.** Выпустите сертификат во внутреннем УЦ организации и пропишите его в nginx директивами `ssl_certificate` и `ssl_certificate_key`. Корневой сертификат УЦ нужно установить на iPhone инженеров.

**6.5.** Установка на iPhone: откройте `https://ВАШ-ДОМЕН/` в Safari и выберите «Поделиться → На экран „Домой“».

## 7. Запуск без Compose (одной командой)

```bash
cd /opt/oto
docker build -t oto-dispatch:latest .
docker volume create oto-data
docker run -d --name oto --restart unless-stopped \
  -p 8080:8080 \
  -e SCALE=1 -e SIM=0 -e TZ=Europe/Moscow \
  -e OTO_PINS="SM-01=7391,AG-01=5520" -e OTO_DEMO=0 \
  -v oto-data:/app/data/runtime \
  oto-dispatch:latest
```

## 8. Где хранятся данные, резервное копирование и обновление

Заявки, журнал, назначения, состояние техники и текущая локация хранятся в файле `/app/data/runtime/store.json` внутри тома `oto_oto-data` (при запуске по разделу 7 — `oto-data`). Том переживает перезапуск, пересборку и обновление контейнера. При `docker stop` сервер сразу записывает состояние на диск (в журнале: «остановка по SIGTERM, данные сохранены»). В файле хранятся последние 4000 записей журнала.

**Резервная копия.** Можно делать на ходу, файл записывается атомарно:

```bash
mkdir -p /opt/oto-backup
docker run --rm -v oto_oto-data:/d -v /opt/oto-backup:/b alpine \
  tar czf /b/oto-$(date +%F_%H%M).tgz -C /d .
```

Ежедневное копирование в 03:00 (`crontab -e`):

```
0 3 * * * docker run --rm -v oto_oto-data:/d -v /opt/oto-backup:/b alpine tar czf /b/oto-$(date +\%F).tgz -C /d . && find /opt/oto-backup -name 'oto-*.tgz' -mtime +30 -delete
```

**Восстановление:**

```bash
docker compose stop
docker run --rm -v oto_oto-data:/d -v /opt/oto-backup:/b alpine \
  sh -c 'rm -rf /d/* && tar xzf /b/oto-2026-11-24_0300.tgz -C /d'
docker compose start
```

**Обновление до новой версии.** Данные сохраняются:

```bash
cd /opt/oto
unzip -o /tmp/ОТО_диспетчеризация.zip      # новая версия поверх старой (docker-compose.yml с вашими правками сохраните заранее)
docker compose up -d --build
docker image prune -f                      # удалить старые слои
```

**Сброс к учебному начальному состоянию.** Эти команды удаляют все заявки и журнал:

```bash
docker compose down -v && docker compose up -d
```

## 9. Своя карта аэродрома (слои QGIS)

Карту можно заменить двумя способами.

- **Без пересборки.** Начальник смены во вкладке «Карта», в блоке «Слои GeoJSON (QGIS)», выбирает файлы слоёв, а затем нажимает «Загрузить как локацию». Карта сохраняется в томе данных. При смене локации заявки и журнал сбрасываются (интерфейс предупредит об этом), поэтому перед заменой сделайте резервную копию (раздел 8).
- **Встроить в образ.** Положите свои файлы в `data/geo/` вместо прежних (`roads.geojson`, `service_zones.geojson`, `objects.geojson`, `airport_boundaries.geojson`, система координат EPSG:4326) и выполните `docker compose up -d --build`. Новая карта применится только после сброса данных из раздела 8 или после загрузки её во вкладке «Карта». Иначе сервер продолжит работать с прежней локацией из тома. В обоих случаях заявки и журнал начинаются заново.

Требования к слоям такие же, как сейчас:

- в `roads` атрибут `type` принимает значения `service`, `pedestrian`, `taxi` или `runway`, а у `service` атрибут `spd_kmh` равен 5, 8, 10 или 20;
- объекты распознаются по названию: «Терминал», «Ангар» (база ОТО), «Стоянка спецтехники», «Склад…», «Взлётно-посадочная полоса».

## 10. Сервер без доступа в интернет (перенос готового образа)

На любой машине с интернетом и Docker:

```bash
cd oto && docker build -t oto-dispatch:latest .
docker save oto-dispatch:latest | gzip > oto-dispatch.tar.gz      # ~60 МБ
```

На целевом сервере:

```bash
gunzip -c oto-dispatch.tar.gz | docker load
cd /opt/oto && docker compose up -d       # без --build: используется загруженный образ
```

Без интернета на карте недоступна только подложка OSM или спутник. По умолчанию она и так выключена, схема аэродрома и все расчёты работают.

## 11. Безопасность

- **Учебные PIN общеизвестны.** Они записаны в документации и подставляются на экране входа. Для эксплуатации обязательно задайте `OTO_PINS` и `OTO_DEMO: 0` (раздел 4).
- **Лучше не выставлять сервер в интернет.** Оставьте его во внутренней сети или VPN. Если внешний доступ нужен, используйте только HTTPS (раздел 6) и ограничьте адреса в nginx: `allow 10.0.0.0/8; deny all;`.
- **Ключ внешней интеграции.** Учётная запись `svc-aodb` предназначена для подачи заявок из внешних систем; смените её ключ через `OTO_PINS`.
- **Изоляция контейнера.** Он работает от непривилегированного пользователя `node`, а наружу открыт только порт приложения.

## 12. Проверка установки

```bash
cd /opt/oto && sh test/docker-e2e.sh
```

Скрипт собирает тестовый образ и на временном порту 8090 проверяет:

- интерфейс и PWA;
- вход и создание заявки;
- сохранение данных после остановки;
- чат;
- имитатор и healthcheck;
- замену PIN.

В конце скрипт выводит «ГОТОВО: все шаги пройдены» и удаляет за собой тестовый контейнер и том. Он вызывает `sudo docker` и запускает контейнеры в сети хоста (`--network host`), поэтому порт 8090 должен быть свободен. Для запуска нужны `curl` и `node`.

Быстрая ручная проверка:

```bash
curl -s http://127.0.0.1:8080/api/v1/health
curl -s -X POST http://127.0.0.1:8080/api/v1/auth/login -H 'Content-Type: application/json' \
     -d '{"userId":"SM-01","pin":"2468"}'          # → {"token":"…", …}
```

## 13. Неполадки

| Признак | Причина и решение |
|---|---|
| `docker compose ps` показывает `unhealthy` или `Restarting` | `docker compose logs oto`. Частая причина — порт занят: поменяйте левую часть в `ports:`, например `"9080:8080"` |
| Страница не открывается с другого компьютера | Межсетевой экран: `sudo ufw allow 8080/tcp`, либо проверьте `ports:`: при `127.0.0.1:8080:8080` доступ есть только через nginx |
| Чат в исходной программе пишет «офлайн» | За прокси не передаются заголовки WebSocket. Используйте `deploy/nginx-oto.conf`: в нём есть блок `location /ws/` с `Upgrade` и `Connection` |
| Импорт большого GeoJSON-слоя завершается ошибкой 413 | Увеличьте `client_max_body_size` в nginx |
| Неверный PIN после обновления | Проверьте `OTO_PINS`. В журнале при запуске должно быть «Доступ: заменено PIN/ключей — N» |
| Нет подложки OSM или спутника | У браузера пользователя нет интернета. Схема аэродрома работает и без подложки |
| Время в журнале сдвинуто | Задайте `TZ` в `environment` |
| Нужно «начать с нуля» | `docker compose down -v && docker compose up -d` (удаляет данные, раздел 8) |
| Сборка падает на `docker build` без интернета | Перенесите готовый образ (раздел 10) |
